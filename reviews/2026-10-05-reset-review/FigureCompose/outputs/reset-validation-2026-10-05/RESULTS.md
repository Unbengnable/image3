# FigureCompose 下一阶段验证实验报告

2026-10-05。本次已派发并执行三个限定实验，由两名独立作者和一名审阅子代理完成。结果支持继续验证轻量工作流，但没有得到新的可接受成品：两张 MAE SVG 在当前预览中科学关系正确，均出现 Inkscape 裁片溢出，实验交付状态为 REVISE。此前 accepted artifacts 保持原字节。

## 实验验证的假设

|实验|假设|实际操作|结论边界|
|---|---|---|---|
|E1：已有 Diffusion Policy 独立复审|旧自评通过的成品，在新审阅者先读图、后读来源时，仍可恢复核心机制，且可实际编辑|先保存读图解释，再查科学来源；在副本把 Ta=4 改为 3；Inkscape 导入、另存、导出并查看|科学关系与这一项编辑成立；发现三处视觉关联歧义，不能继承“全面发表级 PASS”|
|E2：项目新案例 MAE|在不给原图、限制迭代的条件下，设计原则能迁移到一个空间机制案例|同一科学输入包、178 mm 主尺寸；冻结后审查四个可见位置、十二个 mask、恢复顺序与 masked-only loss；另做 50% 副本|当前渲染的机制与语义修改成立；编辑器交付未通过，不能声称整个产品已泛化|
|E3：同一输入两条路线|PNG→SVG 是否对每种机制图都必要，其视觉收益与重建代价是什么|R：一次 imagegen 后重建 SVG；V：直接原生 SVG；两位作者互不查看对方；分别保存草稿、批评、次数与成本|直接 SVG 在此例能表达科学机制和空间内容；不能凭一个非随机对照宣布路线优胜|

预注册方案：[PROTOCOL.md](PROTOCOL.md)。科学输入依据 MAE [原论文 Section 3](https://arxiv.org/html/2111.06377v3#S3)，原文段落与来源哈希保存在本目录。MAE 是项目新案例，不能保证模型从未见过该方法。输入包由协调者准备，本次没有测试从模糊自然语言自动完成科学提取和参考检索。

## 防范照抄、空线框与无限微调

作者没有接收参考图、目标论文图、参考裁片或布局。协调者只看过 DB005、DB082 各一次，抽象成“用空间变化解释操作”和“颜色保持语义一致”两条文字原则。两位作者先记录自己的设计决定，之后才产图。目标论文图和参考原图只在双方主图冻结后供审阅使用，未用于反复修图。协调者在准备来源时见过目标图注，这一暴露已明确记录。

R 限一次生成、至多一次对自身草稿的生图编辑，实际没有生图编辑。两条路线均只有一份 SVG 初稿和一次集中科学/视觉修订；V 另有一次缺字渲染修复。双方主图冻结后只执行规定的 50% 语义副本，不接收审阅反馈、不修复兼容性失败。全部草稿和错误保留。

视觉检查要求能追踪真实空间内容、移除 patch、稀疏输入、位置恢复和损失区域。不能靠框数、颜色或“有插画”判通过。独立读图确认：V 的山湖图像与裁片、R 的帆船图像与裁片确实承担空间解释，均超过空框箭头组合。不过两图仍大量使用 operator 框和箭头，本例不证明所有方法的视觉语言问题已解决。

这是一套可审计的行为约束，而非操作系统隔离；同模型参数记忆也无法排除。原图对照只能判断已观察到的素材与非必要构图相似性，不能证明绝对原创。完整审阅与暴露顺序见 [final-review/REVIEW.md](final-review/REVIEW.md)。

实际冻结后审计未发现 DB005 的马/斑马素材与三段灰底流程、DB082 的人体时间轴与嵌套分组、MAE 原图的火烈鸟素材和长 token 列布局被照搬。方法规定的 encoder→decoder 顺序及空间 patch 不是照抄判据。此项为独立审阅的“未观察到照搬”，不是统计相似度或版权认证。

## 实际结果

|维度|Diffusion Policy 成品复审|MAE V：直接 SVG|MAE R：imagegen→SVG|
|---|---|---|---|
|交付预览与来源科学关系|PASS，限原有推理范围|PASS，限已检查的 CairoSVG 渲染和预训练范围|最终 SVG PASS；原始生成 PNG FAIL|
|机制的视觉表达|PARTIAL：预测终点、执行选择、backbone 关联存在歧义|可恢复稀疏编码与空间恢复，有有效图像内容|可恢复移除、恢复及空间监督，有有效图像内容|
|真实尺寸可读性|PARTIAL；小下标约 5.95 pt|小下标 5.10 pt，纸面/人类检查未执行|索引约 6.05 pt，纸面/人类检查未执行|
|实际语义编辑|PASS：Ta 4→3；To=2、Tp=8 保持|PASS：可见数、mask、位置、loss、caption 4/12→8/8|PASS：同样传播；八个裁片变窄，存在比例变形|
|原生编辑器视觉兼容|Inkscape CLI 导入/另存/导出 PASS，GUI 操作未执行|FAIL：裁片溢出遮挡稀疏输入区域|FAIL：裁片溢出遮挡稀疏输入区域|
|本次状态|PARTIAL/PENDING；历史接受记录不改|REVISE，不纳入 accepted artifacts|REVISE，不纳入 accepted artifacts|

Diffusion Policy 的 [独立复审](existing-review/REVIEW.md) 没有发现明确科学矛盾，但指出 A_t^0 的箭头只进入淡色尾部、执行路径从上方 bracket 发出、替代 backbone inset 与 predictor 关系偏弱。它没有复查原 Stage 1 PNG，所以不能替旧 gate D 背书。实际修改与原生导出只发生在副本。

MAE 原始生成 PNG 有四个可见输入，却只画出三个编码输出块；恢复位置标注的次序也有问题，损失目标示意包含灰色隐藏区。SVG 修复了这些内容，但 PNG 的科学失败记录保持 FAIL。高质量插画不能替代计数和拓扑审查。

两个 SVG 的科学标签、位置与路由都是原生元素。V 为 51 个 text、0 image，178×82 mm；R 为 114 个 text、2 个本地嵌入场景裁片，178×99.68 mm。R 没有把整张图包进 SVG，场景插画内部仍不可按矢量编辑。元素数量只是结构证据。

本次最关键的新失败是跨工具裁片语义。Inkscape 成功打开并保留 text，却把选中的小 patch 画成多个完整场景，遮挡编码输入。直接导出原始副本与另存后导出的 PNG 哈希相同，说明问题已存在于原始 SVG 的该工具渲染，不能归咎于另存丢失。协调者也实际查看并确认了失败。详见 [native-editor/check.json](final-review/native-editor/check.json)，失败预览为 [V](final-review/native-editor/X-direct-178mm.png) 与 [R](final-review/native-editor/Y-direct-178mm.png)。本轮没有修复或扩大工具矩阵。

|测量项|V|R|

|集中 SVG 修订|1|1|

成本来自 [V cost](arm-vector/cost.json) 与 [R provenance](arm-raster/cost-provenance.json)。计时起点不同，报告制作和独立审阅另有成本；没有 token、订阅金额或准确活跃思考时间。两位作者、两套操作预算、一次案例不能构成因果效率比较，也不能据额外 API 费用为零称“工作流零成本”。

实际产物证明：两种路由都能在有限迭代下得到可读的当前预览，两个真实语义修改保持科学一致；原生工具检查暴露两张图的交付失败，旧 Diffusion 图在同一工具中通过。作者自评、独立读图、来源核验、结构检查分别留档，没有混成总分。审阅者与作者分开上下文，但仍是同模型子代理，没有人类用户研究、不同模型复现或纸面打样。

协调者对“直接 SVG 可以承担某些空间机制图”持支持性判断；对“所有图都需要先生成完整 PNG”持保留判断。这些是本例推断。少参考或只给抽象原则是否优于真实图参考、跨领域是否稳定、科学输入能否自动提取，都仍未验证。

## 本轮之后值得验证什么

第一，验证简单且可移植的局部场景裁片能否同时通过当前 renderer 和实际编辑器，并在一次语义修改后保持一致。这是眼前的交付假设；只需对副本进行有限修复与重测，不需要新图谱、DSL 或绘图框架。本轮没有执行该修复。

第二，在最多两三个不同机制的新案例上，测试“精确机制优先直接 editable，复杂场景按需使用 imagegen 局部素材”的选择原则。仍固定预算、先冻结后审阅，衡量科学错误、空间解释和重建代价。MAE 单例只能说明直接 SVG 有可行性，不能决定默认路线；复杂拓扑与高信息密度尚未被本轮覆盖。

第三，用一次 178 mm 的实际人类读图/纸面检查验证小索引和监督分支是否影响机制恢复。要求读者说出 encoder 输入、mask 插入位置、loss 范围，而非只问“好不好看”。本次同模型读图与大屏预览不能替代这一证据。

暂不扩建参考数据集、训练风格分类器、引入新付费模型、恢复 LocalFigure 编排或建设通用 SVG 重建系统；不继续照原图逐处调到相似，不追加 MAE 主图修图，不修 FAST/DreamerV3，不改 Stage 1/2 生产约定，不把实验候选升级为 accepted。

全部实验文件位于本目录。此前 163 个输出文件零变化、零缺失：[integrity-check.json](integrity-check.json)；四份共同输入哈希未变：[shared-input-integrity.json](shared-input-integrity.json)。本次得到的是路线选择与交付风险的证据，最值得推进的是轻量验证与明确失败边界，而不是把单例包装成更大的架构。
